## 2. 부팅 검증 결과 요약

| 항목 | 결과 |
|------|------|
| BSP | L4T R36.5.2 ✅ |
| 커널 | `5.15.199-l4t-r36.5`, 빌드 산출물과 git 해시 일치 ✅ |
| rootfs | `/dev/mmcblk0p1` (ext4) ✅ |
| eMMC | 59.3G (64 GB). 파티션 15개가 `flash.xml` 과 일치 ✅ |
| GPU | `nvgpu`, `nvmap` 로드 ✅ |
| 실패 서비스 | `nvpmodel` (ISSUE-002), `systemd-networkd-wait-online` (네트워크 링크 없음 추정) ⚠ |

**결론:** D315AO의 eMMC 부팅까지는 커스텀 레이어 없이 된다. 이는 "부팅 체인은 개발킷과 같고, 다른 것은 MB1 pinmux/GPIO와 커널 DTB"라는 기존 분석과 맞는다.

## 5. 다음 할 일

1. **보드 확인 (1단계 마무리)**
   - `reboot` 후 `findmnt /`
   - `df -h /`: rootfs ext4가 28 GiB 그대로인지, 파티션 크기(57.8G)까지 확장됐는지
   - `journalctl -b -u nvpmodel`, `nproc`: ISSUE-002 원인 확정
   - `ip -br link`
2. **ISSUE-002 조치.** `local.conf` 에 `NVPMODEL = "nvpmodel_p3701_0004"` 를 넣고 다시 빌드·플래시해 확인한다.
3. **2단계 착수.** 가이드 8.4의 로그(`dmesg`, `lsusb -t`, `gpio` 등)를 수집하고, 개발킷 DTB/pinmux와 D315AO의 실제 차이를 기록한다.
4. **문서 정리.** `sdk-guide/README.md` 의 MACHINE 표기(`...-0005`)에 SKU 0004 사용 사실을 반영한다.
