- 사용자 입력 내용 정리: Jenkins 2.445 버전을 Docker 환경에서 `.war` 파일 덮어쓰기 방식으로 2.573 버전으로 업그레이드한 후, Java 버전 미달(요구사항 Java 21 이상, 현재 Java 17) 오류로 인해 컨테이너가 시작되지 않는 문제 발생.
    
- Gemini의 응답 요약 : Jenkins 2.573 버전의 Java 요구사항(Java 21)을 충족하기 위해 Docker 이미지 자체를 `jenkins/jenkins:2.573-jdk21` 등 최신 태그로 교체하여 컨테이너를 다시 띄워야 합니다.
    
- 응답 :
    

원인은 에러 메시지에 명확하게 나와 있듯이, **Jenkins 2.573 버전부터는 구동에 최소 Java 21 버전이 필요**하기 때문입니다. 현재 기존 Docker 컨테이너 내부 환경은 Java 17로 세팅되어 있어 새 `.war` 파일을 실행하지 못하고 있습니다.

Docker 환경에서 단순히 `.war` 파일만 덮어씌우는 방식은 컨테이너 내부의 Java 버전(런타임 환경)을 바꾸지 못하므로 이 문제가 발생합니다. 가장 안전하고 올바른 해결책은 **원하는 Jenkins 버전과 Java 21이 함께 패키징된 공식 Docker 이미지로 컨테이너를 새로 생성**하는 것입니다.

기존 데이터(볼륨)가 안전하게 호스트 컴퓨터에 마운트(연결)되어 있다는 가정하에 아래 순서대로 작업을 진행해 보세요.

### 해결 순서

## 1. 기존 컨테이너 중지 및 삭제

기존 컨테이너를 안전하게 중지하고 삭제합니다. (볼륨 매핑이 잘 되어 있다면 데이터는 날아가지 않습니다.)

Bash

```
docker stop <기존_컨테이너_이름>
docker rm <기존_컨테이너_이름>
```

## 2. Java 21이 포함된 최신 Jenkins 이미지로 재시작

기존에 사용하시던 `docker run` 명령어에서 이미지 태그만 **`jenkins/jenkins:2.573-jdk21`** 또는 **`jenkins/jenkins:lts-jdk21`** 형태로 변경하여 실행합니다.

Bash

```
docker run -d \
  --name jenkins \
  -p 8080:8080 -p 50000:50000 \
  -v /기존/호스트/데이터/경로:/var/jenkins_home \
  jenkins/jenkins:2.573-jdk21
```

> **주의:** `-v` 옵션 뒤의 호스트 경로(`기존/호스트/데이터/경로`)는 반드시 이전에 사용하시던 데이터 경로와 일치해야 기존 설정과 플러그인이 그대로 유지됩니다.

> **근거 및 참고사항:** Jenkins 공식 문서에 따르면, 2024년 말 이후 출시된 최신 주간(Weekly) 및 LTS 버전들은 점진적으로 Java 11/17 지원을 중단하고 Java 21을 필수 요구사항으로 채택하고 있습니다. 따라서 war 파일만 바꾸기보다 공식 Docker 이미지를 업데이트하는 것이 권장되는 표준 업그레이드 방법입니다.
