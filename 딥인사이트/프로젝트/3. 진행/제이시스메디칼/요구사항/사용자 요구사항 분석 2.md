# 무선 실시간 영상 전송 기술 분석 및 제안

## 1. 무선 통신 환경 및 채널 전략

### 1.1 Wi-Fi 자동 채널 변경의 위험성
일반적인 Wi-Fi의 자동 기능은 **Mission Critical(실시간성 필수)** 시스템에서 치명적인 블랙아웃을 유발할 수 있습니다.

| 기능 | 동작 방식 | 드론/의료기기 적용 시 문제점 |
| :--- | :--- | :--- |
| **ACS (Auto Channel Selection)** | 간섭이 적은 채널로 자동 이동 | 채널 변경 시 재연결에 **2~5초 소요** $\rightarrow$ 영상 끊김 발생 |
| **Band Steering** | 신호 강도에 따라 2.4GHz $\leftrightarrow$ 5GHz 이동 | 밴드 전환 순간 **패킷 손실 및 딜레이** 발생 |

> **비교**: 전문 드론의 **FHSS(주파수 도약)** 기술은 초당 수백 번 주파수를 바꿔 끊김이 없으나, 표준 Wi-Fi 모듈과 iPad 환경에서는 구현이 불가능합니다.

### 1.2 현실적인 무선 최적화 전략
- **고정 채널 사용 (Manual Selection)**: DFS(기상 레이더) 간섭이 없는 **Non-DFS 채널**(36, 40, 44, 48 / 149, 153, 157, 161) 중 하나를 고정 사용.
- **적응형 비트레이트 (Adaptive Bitrate)**: RSSI(신호 강도) 저하 시 GStreamer 등을 통해 비트레이트를 낮춰 끊김 방지.
- **물리적 보강**: MIMO 안테나 다이버시티 적용으로 수신 감도 향상.

## 2. 영상 전송 프로토콜 분석 및 추천

### 2.1 환경 분석
- **연결 구조**: 1:1 (카메라 $\rightarrow$ iPad) / 로컬 Wi-Fi
- **핵심 요구사항**: 초저지연(Real-time), 고화질(피부 정밀 확인), 안정성(시술 중 끊김 방지)

### 2.2 프로토콜별 비교 분석

| 항목 | WebRTC ⭐ (추천) | RTSP/RTP | SRT |
| :--- | :--- | :--- | :--- |
| **iPad 호환성** | 우수 (Native SDK 풍부) | 보통 (VLCKit 등 필요) | 보통 (전용 플레이어 필요) |
| **지연 시간** | **최저 (~100ms 이하)** | 중간~큼 (버퍼 발생) | 중간 (수백 ms) |
| **보안/암호화** | DTLS-SRTP 기본 내장 | 별도 구성 필요 | 암호화 내장 |
| **네트워크 적응** | NACK/PLI/FEC 표준 지원 | 구현별 상이 | 손실 복구 강함 (지연 $\uparrow$) |
| **구현 난이도** | 중 (시그널링 서버 필요) | 중 (플레이어 설정) | 중 (생태계 제한적) |

### 2.3 최종 추천 아키텍처: WebRTC P2P
**"최저지연 + iOS 호환성 + 보안"**을 모두 충족하는 최적안입니다.

#### [구현 세부 사양]
- **카메라 HW**: $\text{Sensor} \rightarrow \text{ISP} \rightarrow \text{H.264 HW Encoder (B-frame OFF, Short GOP)} \rightarrow \text{libwebrtc/GStreamer webrtcbin}$
- **iPad App**: $\text{Google WebRTC iOS SDK} \rightarrow \text{VideoToolbox HW Decoding} \rightarrow \text{AVSampleBufferDisplayLayer}$
- **시그널링**: 가벼운 WebSocket 또는 WHIP/WHEP 프로토콜 사용.

## 3. 최적화를 위한 설정 가이드 (Low-Latency Preset)
### 3.1 코덱 및 전송 파라미터
- **해상도/FPS**: $1080p30$ 또는 $720p60$ (상호작용 체감 향상을 위해 60fps 권장).
- **비트레이트**: $4 \sim 8\text{ Mbps}$ (신호 강도에 따라 가변 적용).
- **GOP 설정**: IDR 주기 짧게 ($0.5 \sim 1.0\text{s}$), **B-frame 제거**, Intra-Refresh 활성화.

### 3.2 네트워크 및 RF 설계
- **대역폭**: $5\text{GHz (UNII)}$ 고정 채널, $20 \sim 40\text{MHz}$ 대역폭 사용.
- **링크 마진**: 실내 반사/차폐를 고려하여 $>10 \sim 15\text{dB}$ 여유 확보.

## 4. 의료기기 관점의 추가 고려사항 (GMP/인증)
1. **지연시간 문서화**: GMP 인증 시 영상 지연 스펙(Glass-to-Glass) 명시 필요.
2. **데이터 보안**: 환자 개인정보 보호를 위해 전송 구간 암호화 필수 (WebRTC 기본 적용).
3. **안정성 검증**: 장시간($>2\text{h}$) 연속 운용 시 발열로 인한 스로틀링 및 프레임 드롭 테스트 필요.
