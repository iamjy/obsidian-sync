# 🛡️ 보안 부팅 및 암호화 핵심 용어 정리

본 문서는 **임베디드 시스템 및 NVIDIA Jetson** 환경에서 데이터와 펌웨어를 보호하기 위해 사용되는 핵심 보안 용어를 해설합니다. [[1](https://docs.nvidia.com/jetson/archives/r35.6.2/DeveloperGuide/SD/Security/SecureBoot.html), [2](https://openvela.csdn.net/694bbbd45b9f5f31781a59d6.html)]

---

## 1. 핵심 용어 정의

### 🚀 보안 부트 ( Secure Boot )
- **정의**: 기기 부팅 시 변조되지 않은 **인증된 정품 소프트웨어(OS 및 펌웨어)만 실행**되도록 보장하는 기술입니다.
- **목적**: 부팅 단계에서 악성코드가 삽입되는 것을 원천 방지합니다. [[1](https://openvela.csdn.net/694bbbd45b9f5f31781a59d6.html)]
### 🔑 PKC ( Public Key Cryptography )
- **정의**: **비대칭 암호화(공개키 암호화 방식)**를 의미하며, 하드웨어적으로는 칩에 기록된 **공개키 해시(Public Key Hash)**를 뜻합니다. [[1](https://docs.nvidia.com/jetson/archives/r35.6.2/DeveloperGuide/SD/Security/SecureBoot.html)]
- **역할**: 제조사가 서명한 디지털 서명의 유효성을 검증하며, 불일치 시 부팅을 차단합니다.
- 💡 *(참고)*: SW 라이선스 문맥에서는 '제품 키 카드(Product Key Card)'를 의미하기도 합니다.

### 🔐 SBK ( Secure Boot Key )
- **정의**: 보안 부팅 내부에서 사용하는 **대칭 암호화 키**입니다. [[1](https://docs.nvidia.com/jetson/archives/r35.6.2/DeveloperGuide/SD/Security/SecureBoot.html)]
- **역할**: 부트로더 및 중요 데이터를 암호화하여 물리적 칩 분석으로부터 **기밀성을 보호**합니다.
- **특징**: OTP(One-Time Programmable) 방식을 통해 내부 퓨즈 영역에 저장되어 외부 노출이 불가능합니다.

---

## 2. PKC vs SBK 비교 분석

### 📊 요약 비교표
| 용어 | 전체 명칭 | 주요 역할 | 특징 |
| :--- | :--- | :--- | :--- |
| **보안 부트** | Secure Boot | 정품 SW 검증 및 보호 | 시스템 보안의 기초 단계 |
| **PKC** | Public Key Cryptography | 위·변조 방지 (서명 검증) | 비대칭 키 방식 (공개키/개인키) |
| **SBK** | Secure Boot Key | 데이터 유출 방지 (암호화) | 대칭 키 방식 (단일 키) |

### 🔍 핵심 차이점 상세
| 구분 | PKC (Public Key Cryptography) | SBK (Secure Boot Key) |
| :--- | :--- | :--- |
| **주요 역할** | 부팅 이미지의 **무결성 및 신뢰성 검증** | 부트로더 등의 **데이터 기밀성 보호** |
| **암호화 방식** | **비대칭키** (RSA-2K/3K 키 쌍) | **대칭키** (특정 바이트 규격 비밀키) |
| **작동 원리** | 개인키 서명 $\rightarrow$ 퓨즈의 공개키 해시와 비교 | 내장된 SBK 키를 이용해 암호화 이미지 복호화 |
| **필수 여부** | 시큐어 부트 활성화를 위한 **필수 조건** | 선택 사항 (단, PKC가 먼저 활성화되어야 함) |

> [!TIP]
> 보통 PKC와 SBK가 결합된 **SBKPKC 모드**를 사용하여 하드웨어 무단 복제와 해킹을 동시에 차단합니다.

## 3. [심화] 비대칭 암호화 (PKC) 쉽게 이해하기

비대칭 암호화는 **"짝을 이루는 두 개의 서로 다른 열쇠"**를 사용하는 방식입니다.

### 🔑 키 쌍의 구성
1. **공개키 (Public Key)**: 누구나 가질 수 있는 열쇠 $\rightarrow$ **[잠그기 전용]**
2. **개인키 (Private Key)**: 소유자만 가진 비밀 열쇠 $\rightarrow$ **[열기 전용]**
- **핵심**: 공개키로 잠근 데이터는 오직 짝이 맞는 개인키로만 열 수 있습니다.
### 📮 비유: "열린 자물쇠가 달린 우체통"
1. **배포**: 영희가 열려 있는 자물쇠(**공개키**)를 사람들에게 나누어 줍니다. (열쇠는 본인만 소지)
2. **암호화**: 철수가 편지를 쓰고, 받은 자물쇠로 함을 잠급니다. 이제 철수 자신도 다시 열 수 없습니다.
3. **복호화**: 영희가 자신의 비밀 열쇠(**개인키**)로 자물쇠를 열어 편지를 읽습니다.
### ✍️ 반대 활용: "전자서명 (Digital Signature)"

전자서명은 데이터를 숨기는 것이 아니라, **작성자의 신원을 증명**하는 것이 목적입니다.

#### 💡 암호화 vs 전자서명의 차이
- **비밀 편지(암호화)**: "아무도 못 보게 숨기는 것" $\rightarrow$ `공개키로 잠그기` $\rightarrow$ `개인키로 열기`
- **전자서명(인증)**: "내가 썼음을 증명하는 것" $\rightarrow$ `개인키로 잠그기(서명)` $\rightarrow$ `공개키로 확인`

#### 🔑 비유: 인감도장과 도장 등록대장
이해를 돕기 위해 **'인감도장(개인키)'**과 **'등록대장(공개키)'**으로 비유해 보겠습니다.
1. **준비**: 영희는 세상에 하나뿐인 **인감도장(개인키)**을 금고에 보관하고, 동사무소에는 누구나 볼 수 있는 **도장 문양 대조표(공개키)**를 등록합니다.
2. **서명**: 영희가 문서 끝에 자신의 인감도장을 쾅 찍어 전송합니다. (문서 내용은 공개된 상태)
3. **검증**: 철수는 동사무소의 **대조표(공개키)**를 가져와 문서의 도장 자국과 맞춰봅니다.
4. **결론**: 문양이 일치한다면, 오직 영희만이 가진 도장으로 찍은 것이므로 **"이 문서는 영희가 작성한 것이 확실하다"**고 신뢰하게 됩니다.

> [!IMPORTANT] **핵심 원리**
> - **"개인키로 잠근다"**: 문서를 숨기는 것이 아니라, 오직 소유자만 만들 수 있는 **'암호학적 직인'**을 찍는 행위입니다.
> - **"공개키로 확인한다"**: 공개된 검증 도구로 그 **'직인의 진위'**를 대조하는 행위입니다.
> - **근거**: 비대칭키 알고리즘(RSA, ECDSA 등)의 수학적 가역성(한쪽 키로 연산한 값은 대응하는 다른 키로만 검증 가능한 특성)에 기반합니다.

### 🚀 사용 이유 및 사례
- **안전한 키 전달**: 비밀번호를 직접 주고받을 필요 없이 공개키만 배포해도 안전한 통신이 가능합니다.
- **활용 사례**: HTTPS(웹 보안), 블록체인, 전자 서명, 임베디드 시큐어 부트 검증 등.
> [!INFO] 
> 비대칭 암호화는 연산 속도가 느려 실제로는 '대칭키'를 안전하게 주고받는 용도로만 사용하고, 대용량 데이터 통신은 빠른 **'대칭키(AES 등)'** 방식을 혼합하여 사용합니다.
